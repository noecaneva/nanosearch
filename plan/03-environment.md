# 03. Environment

The environment is a text game. The model writes actions inside tags, the environment answers
inside tags, and the episode ends when the model stops or the budget runs out.

## Why tags rather than JSON tool calls

A 1.5B instruction-tuned model emits well-formed JSON unreliably, and a 0.5B one emits it badly
enough that format failures would dominate the results. Tags are far easier to produce, trivial to
parse with a regex, and easy to reward partially. The cost is that this is not the interface a
production system would use, which the write-up should say plainly.

## Action space

The model may emit exactly two actions.

```
<search>the query text</search>
<done/>
```

Reasoning before an action is allowed and encouraged inside `<think>...</think>`, which is parsed
out and ignored by the environment but is still model-generated, so it still receives gradient.

## Environment response

```
<result>
[1] <title> | <first 200 tokens of passage>
[2] ...
[3] ...
</result>
```

Three passages per search, truncated. Truncation keeps episodes short at this model size, where
context length is the binding constraint long before reasoning quality is.

## Episode protocol

1. Environment presents the question with a system prompt describing the two actions.
2. Model generates until it closes a `</search>` or emits `<done/>`, or hits the per-turn token cap.
3. On `<search>`: the environment retrieves 3 passages and appends a `<result>` block.
4. Repeat from step 2.
5. Episode ends on `<done/>`, on the third completed search, or on a malformed action.
6. Final retrieved set is the deduplicated union of every passage returned, at most 9.

## Hard limits

| Limit | Value | Reason |
|---|---|---|
| Max searches | 3 | Bounds the reward and keeps the rollout short |
| Passages per search | 3 | Final budget of 9 matches the baselines |
| Tokens per turn | 256 | A small model that rambles is not producing a better query |
| Total episode tokens | 2048 | Fits comfortably in context with three result blocks |

## Malformed actions

A malformed action ends the episode immediately with whatever has been retrieved so far, and the
format reward is not paid. Do not silently repair the model's output. Repairing it hides the format
failure rate, which is one of the things you are trying to measure at this model size.

The one exception worth considering is an unclosed `</search>` tag at the token cap, which is a
truncation artifact rather than a formatting failure. Decide the rule up front, write it down here,
and apply it identically to the prompted baseline and the trained model.

## Serving

Rollouts are generated by vLLM, not by `model.generate`. Two reasons: it is roughly an order of
magnitude faster for grouped sampling, and it is the thing you are trying to learn.

The consequence is that the trainer and the sampler hold separate copies of the weights, so the
policy in vLLM must be refreshed after each optimizer step. That synchronization is the single
largest implementation risk in this project and is covered in `04-grpo.md` and
`06-schedule-and-risks.md`.

## Determinism

For evaluation, temperature 0 and a fixed seed. For training rollouts, temperature around 1.0,
because GRPO needs within-group variance to produce any gradient at all. A training temperature
that is too low is one of the ways this silently fails to learn, and it looks exactly like a bug in
the loss.
